APS NAATI CCL PRACTICE - FIREBASE CLOUD SYNC V19.5
===================================================

LEARNERS NEVER CONFIGURE FIREBASE.
The Firebase Web configuration is embedded in the GitHub build.
A learner only creates/signs into the same APS account on each device.

WHY V19.5 CHANGES THE FIRESTORE STRUCTURE
-----------------------------------------
Older builds stored nearly all progress in one document:
  apsUserProgress/{userId}

That eventually reaches Firestore's 1 MiB document limit. V19.5 keeps that
root document small and stores progress in scalable child collections:

  apsUserProgress/{userId}
    sections/{progressKey}
    sections/{progressKey}/chunks/{chunkNumber}   (only if a section becomes large)
    myVocabs/{vocabId}

My Vocabs is therefore no longer able to make the main progress document too
large. A single My Vocab edit can sync without rewriting the entire sheet.

ONE-TIME FIRESTORE RULE UPDATE FOR THE APP OWNER
-------------------------------------------------
Firebase Console -> Firestore Database -> Rules
Replace/publish the rules with the following (or merge the nested matches into
your existing equivalent rules):

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    function ownsProgress(userId) {
      return request.auth != null
             && request.auth.uid == userId
             && request.auth.token.firebase.sign_in_provider != 'anonymous'
             && (request.auth.token.email_verified == true
                 || request.auth.token.firebase.sign_in_provider != 'password');
    }

    match /apsUserProgress/{userId} {
      allow read, write: if ownsProgress(userId);

      match /sections/{sectionId} {
        allow read, write: if ownsProgress(userId);

        match /chunks/{chunkId} {
          allow read, write: if ownsProgress(userId);
        }
      }

      match /myVocabs/{vocabId} {
        allow read, write: if ownsProgress(userId);
      }
    }
  }
}

MIGRATION
---------
After publishing the rules:
1. Open V19.5 while signed into the same APS account.
2. Settings -> Cloud progress sync -> Refresh (or Sync now).
3. V19.5 reads the older single-document progress if present.
4. It safely writes progress sections + My Vocabs to the new structure.
5. Only after the new structure is written successfully, the oversized legacy
   `keys` field is removed from the root document.
6. Local progress remains on the device throughout the migration.

If the rules have not yet been updated, V19.5 keeps local progress safe and
shows a clear "Needs attention" message rather than deleting anything.
